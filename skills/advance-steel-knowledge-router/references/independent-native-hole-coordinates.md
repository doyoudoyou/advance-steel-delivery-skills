# Independent source-hole matching

When promoting a probe into the normal selected-IFC candidate, reconcile the default compile branch, stable command, bundle manifest and live Ribbon handler. Exercise the actual packaged build on a fresh differently named writable complete copy; a successful probe or build alone does not verify promotion. Explicitly gate unvalidated model units. Snapshot every current input file and retain the historical baseline comparison; remove stale copied DWL/DWL2 files only from the new isolated destination, never from the source, and report transient-lock exclusions separately from unchanged-file totals.

Measure native ConnectionHolePlate CSExact with Matrix3d.GetCoordSystem and Arranger.GetPoints under read-only DocumentAccess. Transform each 2D arranger point by the source frame origin/x/y and retain native z axis, diameter, depth, feature handle and host ASId. Do not derive source coordinates from prior IFC exports or the IFC feature converter.

Match analytic IFC cutter cylinders using host ASId, axis direction, transverse distance AND finite source-depth coverage before deciding uniqueness. Different holes on parallel folded-plate flanges can be coaxial; infinite-line matching incorrectly calls them duplicates. Do not resolve that ambiguity by list order or wider coordinate tolerances. In the verified normal-hole sample, native CS z is outward and positive Depth extends along negative z. Gate nonzero hole Angle until its semantics are independently verified.

Resolve IFC opening, swept-solid and profile placements, and normalize file units. Distinguish exact nominal diameter equality from documented native converter clearance (0.001 mm radial / 0.002 mm diameter). Report clearance rather than treating it as zero error. For this user's selected-IFC plugin, the accepted product policy is exact native nominal circular-hole diameter, with the extra radial clearance removed from actual IfcCircleProfileDef geometry, not merely metadata. Preserve historical clearance reports and test old output as a negative case under the exact policy. Keep tests for shuffled coaxial holes, missing/duplicate holes, wrong host, lateral shift, reversed axis, wrong diameter, insufficient depth and nonfinite geometry.

Do not trust AS2027 EBInstanceModel.GetDataByType to enumerate newly constructed entities: the observed implementation inserts into the type index using EIN before assigning its new value, causing key-zero collisions. Enumerate the actual public Get/Index/Interval registry with validated index semantics, then verify source host identity and complete per-diameter hole counts. Do not patch Autodesk assemblies or reduce expected counts to fit the partial type index.

Validate source-hole feature descriptions with a shared pure policy: require supported circular type, finite positive diameter/depth, finite zero angle, positive arranger counts and complete host totals with overflow protection. Keep synthetic policy rejection tests distinct from native special-hole end-to-end tests. Capture and consume the same validated inventory from the converter-resolved native map before geometry correction/file writing; an earlier source-list prepass did not cover all resolved objects in the observed workflow. Do not silently reuse an incomplete inventory or infer that untested special holes are supported.

For large diagnostic PickFirst preparations, avoid recursively nested ssadd expressions. A long/deep expression produced AutoLISP continuation and access-violation errors in the observed batch workflow. Use a flat foreach with validated literal handles, reject duplicates, clear stale implied selection first, and require exact resulting count before leaving the selection active. Missing handles must clear the set, never export a partial selection. Verify command/document/output state after any exception; do not rerun blindly or reduce the expected batch to hide the failure.

Before claiming special-feature coverage, census the actual copied model under read-only DocumentAccess and reconcile the complete native host handle set against the earlier inventory. Record per-host read errors and distinguish hole feature groups from individual arranger points. An existing model with only normal circular holes cannot establish native slot/angled-hole acceptance; synthetic policy rejection is separate evidence. Exercise unsupported native objects both alone and mixed with known-good objects, verifying no final/staging output for either rejection.

For straight-beam normal circular holes, read ConnectionHoleBeam.CSExact and arranger points independently, not from IFC. Classify host/feature pairs explicitly: ConnectionHoleBeam belongs to StraightBeam and ConnectionHolePlate to plate-family hosts. Permit native BeamShortening to remain unchanged only within a validated path; do not generalize that exception to other beam cuts or curved-beam holes. Keep a real unmodified-native export as the body/cutting baseline, and check complete nominal circle counts plus source axis/depth coverage. A passing sample does not certify every beam profile.

Separate circular-hole relationships from other IfcRelVoidsElement features such as beam notches. Validate the complete target opening-ID set, rather than assuming every opening is a circular hole.

For unchanged faceted BRep bodies, compare canonical shell/face/loop geometry and placements while preserving winding, bound orientation, shell grouping and exact coordinates. Native face order and cyclic loop starts can vary, so raw mesh triangle indices are not a reliable identity criterion. Still validate effective closed output geometry separately.
