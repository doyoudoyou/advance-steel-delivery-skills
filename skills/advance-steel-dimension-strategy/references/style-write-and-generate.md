# Writing a USER drawing style and checking it by generation (AS2027)

Use after the read-only plan (SKILL.md step 8/9) is approved. Everything here was exercised end to end.

## Write recipe (PowerShell + System.Data.SqlClient, no pyodbc needed)
1. Dry run first: same script without `-Apply` checks every target key is free and every source row exists; abort the whole batch on any taken key.
2. Refuse if `Get-Process acad` returns anything. `sqllocaldb stop AdvanceSteel2027`, copy `GBR\Steel\Data\AstorDetails.mdf/_log.ldf` and `GBR\Kernel\Data\AstorDetailsBase.mdf/_log.ldf` to `Documents\AdvanceSteelTools\backups\<name>_<stamp>\`, compare sizes, `sqllocaldb start`, wait ~8 s.
3. Connect `Server=(localdb)\AdvanceSteel2027;Database=<full upper-case MDF path>`; open ONE transaction; `insert ... select` from the factory row with only the changed columns overridden and `OwnerText='USER'`; check every rowcount.
4. Read back each written value AND one factory row (e.g. source style still `DSC`, unchanged) inside the transaction; commit only if all match, else roll back.
5. Later single-field fixes: `update ... where [Key]=<user key> and OwnerText='USER' and <col>=<expected old>`; never touch factory rows.

Copying a factory row with a few columns changed (works for every DSM table, no column list needed): `select * into #t from <Table> where [Key]=<src>; update #t set [Key]=<new>, RunName='...', OwnerText='USER', <changes>; insert into <Table> select * from #t; drop table #t` inside the transaction. Do not name PowerShell helper functions `Sc`, `Set`, etc.: they collide with built-in aliases (`sc` = Set-Content) and the script fails in confusing ways; use names like `Q1`.

Adding dimension chains to a USER view (one batch per round):
1. Read the view's `DetViewRequest.DimStrategy`, then `DetViewDimStrategyItems` (`[Key]`=strategy Items, ordered by `[Order]`) joined to `DetViewDimRequestLinear` and its `Point1..n` → `DetViewDimPointSelection`. Filter chains along the member by `Direction` (4 = main X along member, 5 = Y in the factory column front strategy).
2. Reuse factory point rules by key; copy a point rule to a USER key only when a column must change (e.g. a reference rule `PointType` 1001 → 1 to make it a measured point).
3. New `DetViewDimRequestLinear` = copy of the closest factory request (keeps arrangement flags), override `[Number of Points]`, `Point1..n`, name.
4. New `DetViewDimStrategyNew` (Items = own key) + one `DetViewDimStrategyItems` row per chain copied from a factory item (Type 2 = ordinary linear chain), then point the USER view's `DimStrategy` at it. A fresh strategy holding only the new chains makes the check clean; the factory chains disappear until re-added, so tell the user first.
5. Read back every row plus the factory strategy's item count. The factory has no 'whole assembly overall length' rule (only main-part contour overall 304).
6. Choose direction and object sets per 'Choosing direction and object set' below; role-based sets only work on models whose parts have roles set.
7. Check values fast from the extents PDF text layer: `re.findall(r'\b\d{2,4}\b', page.get_text())` lists every dimension value on the sheet; if the expected totals (e.g. 4530, 3880) are absent the chain is wrong before any visual reading. To read each chain separately, group `page.get_text('words')` numbers by x (rotated/vertical text) or y (horizontal text): each group is one chain, bottom-to-top / left-to-right. Single-digit leftovers are section marks or labels, not dimensions.

Rows a new assembly style needs: `DetViewRequest` (one per view) + `DetViewRequestCategories`, `DetailStyle` (+`DetailMasterTable`), `DetailStyleMapNew` + `DetailStyleMapItems` (qualifier set -> style, copy Script/overrides from the factory map row), `DetailProcessStep` (StyleMap) + `DetailProcessDefinition` (Step1). A process key that exists only in the DB runs fine through `KernelServices.RunDetailProcess(key, ids)`; it does not need a palette entry.

## Generate one sheet for review
- Run the process on ONE main part handle (not the whole model) on the role-set model copy; move the previous `Details\<sheet>.dwg/.upd` aside first so each round is comparable.
- Convert to PDF without AS: `accoreconsole.exe /i <copy.dwg> /s <scr> /l en-US` with script `FILEDIA 0 / TILEMODE 0 / -EXPORT / PDF / CURRENT / NO / <out.pdf> / QUIT / Y`; render with PyMuPDF from the AdvanceSteelTools venv and inspect. Measure a known dimension line in pixels to estimate the real scale.
- Compare rounds by pixel diff of the rendered pages; identical pixels = the change had no effect.
- Parametrize single-field fix scripts by `-From/-To` with the expected old value in the WHERE clause and a factory sibling row checked in the read-back; one reusable script per knob beats copying with sed (sed edits of quoted SQL are fragile).
- Use a factory process on the same part as the control before blaming the USER rows.

## Harness pitfalls
- Quote the DWG and script paths in the acad.exe launch: `Start-Process -ArgumentList` joins elements with spaces unquoted, so a model named with a space (`Plum Tree_RC.dwg`) is split and AS reports the drawing missing. Renaming the model copy to a space-free name also works.
- Give every generation/read run its own output folder (`<name>_$$`): a timed-out earlier run that is still alive can finish later and overwrite shared result files with a pipe-connect error.
- Run the accoreconsole PDF export and the PyMuPDF render/pixel-diff in background or with a generous timeout; the combined foreground step can exceed 300 s.
- Put the self-built Live Link server and probe DLLs in a folder listed in AS `TRUSTEDPATHS` (append `;<folder>\...` via COM `SetVariable`, keep the old value, leave `SECURELOAD` 1; it persists in the user profile, per machine) and NETLOAD them from there: no Load Once dialog, so generation runs unattended. Without that, each fresh AS waits for the user's Load Once; if the gate times out, report it and wait for the user, do not relaunch on your own.
- End an AS you launched by closing documents and calling COM `app.Quit()`; use `Stop-Process` on your own PID only when AS no longer answers. A forced kill can leave a crash/error-report window that the user sees as "AS crashed". Save the model copy before any shutdown.
- Keep the DB write / generate scripts in the repo (e.g. `tools/dsm-<mark>/` with a README table: script, change, doc section), not only in Hermes scratch: scratch is pruned after ~24 h idle, taking the scripts and the Debug server build with it. On resume, check the scratch files exist, restore scripts from the repo and rebuild the server before launching AS. If the model copy itself is gone, re-copy the user's original DWG + `Databases` folder (copy only) and re-set the part roles on the copy in the SAME AS session that generates the sheet (role script + generate call in one run): roles live in the copy and are lost with it, and one session costs the user only one Load Once. Read the roles back before trusting the sheet.

## Dimension-chain rows (AS2027 tables)
- View -> `DetViewRequest.DimStrategy` -> `DetViewDimStrategyNew` (`Items` = key of its item list) -> `DetViewDimStrategyItems` (same `[Key]`, one row per `[Order]`, `Type` 2 = normal linear chain, `RequestLinear`, plus `HideDimensionPoint/BrokenRunningDimension/GroupEqualDistances`, all 0 in the factory) -> `DetViewDimRequestLinear` (`Direction`; `ArrangeGlobally/ArrangeAbove/AllowCombine/AutomaticallySeparate`; `[Group]`; `[Number of Points]`, `Point1..15`) -> `DetViewDimPointSelection` (`Objects` = object-set key, `PointType` 1 extreme / 2 contour / 3 feature / 4 hole / 9 system, +1000 = reference, `PointGeometricRestrictions`, `MpGeomRestriction`) -> `DetObjQualifierSet` (`Key, RunName, Group, OwnerText`) + `DetObjQualifierSetItem` (`Key, ObjQualifier, ModelRole, Filter, IdDetObjQualifierSet`).
- Column front factory strategy 20025 has 18 chains; `Mp X - Extreme GTA` (73) measures only the main part, not the assembly.
- `[Group]` on a request is a Style Manager category (values 0-12 spread over unrelated chains), not a presentation switch: setting it to the factory overall chain's value changed nothing. The factory 'Overall' chain (304) is overall-only because its two point rules hit only the main-part ends, with the same item `Type` 2.

## Choosing direction and object set (verified on a vertical column front view)
1. Direction from factory request names: 0 `View X` (sheet horizontal), 1 `View Y` (sheet vertical), 2 sloped X, 3 thickness/splay, 4 `Mp X`, 5 `Mp Y`, 6/7/9 curved beams, 10/17 angle/development. Prefer 0 / 1 for sheet-horizontal / vertical chains: they follow the sheet, not the member axes or a `SystemAndBox` flip. On a column front view `Mp Y` (5) is the DEPTH axis, so factory `MainY ...` chains silently draw nothing (same points: 5 = nothing, 0 = chain).
2. Read the object set's members before trusting a rule name: factory role sets are wider than named. `EndPlate, Roles` (10) = Baseplate + Endplate + Coverplate (an end-plate width chain also picks up the base plate); `AttPl, Roles` (128) has 10 members incl. a blank ModelRole that catches every plate, and `128 + PointGeometricRestrictions 8` found no point at all; O4 `AttParts` includes shear studs (O33). O15 `AttPl` = every plate, O107 = Baseplate only.
3. To hit exactly one role: copy the factory set row to a USER key, copy only that role's `DetObjQualifierSetItem` with `IdDetObjQualifierSet` = new set, copy a factory point rule with `Objects` = new set. One role-only set per role is reusable across chains (Endplate-only and Plate-only fixed an 85/5/320/5/85 chain into 5/320/5 and brought back a vanished overall chain).
4. Proven column-front combinations: segment chain `Ref. Mp - Extreme` (40) + O15 rule 6 -> every plate end; opposite side `ArrangeAbove` 0 with 113 `Mp - Extreme` + 20590 `Base Plate Extreme All, Role` + 20550 -> base/end-plate thickness + main length; top width chain Direction 0 with Endplate-only + Plate-only rules; assembly-height chain Direction 1 with 20590 + Plate-only rule -> right points but still split per plate (both ends of each object).
- When a dry-run guard refuses (e.g. a miscounted factory member count), fix the expectation and rerun the dry run before applying; never loosen the guard to make it pass.

## Decoding point-rule restrictions with one diagnostic sheet
- Build a temporary USER strategy where each chain = `Ref. Mp - Extreme` (40) + one test point rule (copy of a factory rule with only `PointGeometricRestrictions`/`MpGeomRestriction` changed), `AllowCombine` 0, plus a known sentinel chain; point the view at it, generate, then revert the view (keep a `-Revert` switch in the same script).
- Read the sheet with PyMuPDF `get_text('words')`, group numbers by x of the rotated text: each group is one chain. Decode which points each chain hit from the segment values against the parts' z ranges.
- AS does NOT lay chains out in strategy order, so identical-looking patterns cannot be tied to a specific code from one sheet; give each test a unique signature or split into batches.
- Verified (O15 plates): restrictions act per object (each plate's top end / bottom end / both ends), never 'only the outermost point of the whole assembly'; Top/Bottom still mean real up/down after front view `SystemAndBox` = Rear. So an overall-only chain across several parts (assembly height) cannot be built from point rules alone; `AllowCombine` 0 and request `[Group]` do not collapse it either. The working alternative: generate the sheet, then add the overall chain as a native AS dimension in a post-generation step (repo `tools/postdim/`; survives save/reopen); offer that or accepting the segmented chain instead of more point-rule rounds.

## A chain that does not appear at all
- One point rule that finds nothing drops the WHOLE chain (a 2-point overall chain vanishes, not shrinks). Turning `AllowCombine` off does not bring it back if a point is missing, so test merging only after the points are proven.
- Isolate the dead rule in one round per rule: replace ONE point rule with a factory rule already proven to find points in this view (e.g. an unrestricted role rule), keep the other, regenerate; the chain reappearing names the culprit.
- Before reusing a factory chain as-is, check its point rules against combinations already proven in this view: a factory request whose rules use a failing combination (e.g. O128 + Top, or a role absent from the model such as Hip Plate) produces nothing. Rebuild it as a USER request with proven rules instead.

## Findings that cost rounds
- The process step's `AlternativeScales` set overrides the view's own `Scale`: AS picks from the set (factory assembly set 13 = 1:5/10/15/20, so 1:25 became 1:20). Point the USER step at set 16 (`None`) to make the view scale stick.
- Top/bottom flip of a column is NOT controlled by `DetailStyle.DetailOrientation` (values 1, 3, 4 all gave the same sheet; the factory process draws it upside down too) and `DetailProcessStep.CoordSystemSelector` has only value 1 in every factory step. The knob that works is the USER front view's `DetViewRequest.SystemAndBox` (`DetViewSystemAndBox`: 1 Object Front, 2 Rear, 3 Top, 4 Bottom, 5 Left, 6 Right, 16 UCS): Front -> Rear (2) is a 180° turn about the member axis (companion views and section arrows flip with it). It fixed one column only; sibling columns came out horizontal or upside down because AS orients the assembly from its attached parts, not the main-part axes (see `dsm-layout-knobs-as2027.md`). Generate every mark of the family before accepting an orientation knob, and use the per-assembly detailing direction (`_AstM14SetAssemblyDetCS`, run per column with `TILEMODE=1`) for the real fix; with it the front view stays Object Front. Avoid UCS (16): it depends on the UCS active at generation time.
- After changing `SystemAndBox`, re-check every other view in the style: a 'bottom' view now looks at the other end of the member, so a view meant as the base-plate plan may show the top connection instead.
- When a knob keeps having no effect, offer the user the option to park orientation (they flip by hand after generation) and move on to dimension chains, instead of grinding through every value.
- The finished sheet's `.upd` sidecar (UTF-16) names the machine, process, style and scale it was generated with: decode with `utf-16-le` and grep for `1:`/style names. A finished sheet whose scale is not in the process's scale set, or whose orientation differs from a fresh factory sheet of the same style, was edited by hand; ask the user, and if so the style itself must produce it.
- accoreconsole `-EXPORT PDF CURRENT` plots only the layout/frame window, so anything AS placed outside the frame is cut off and invisible. To check frame overflow, plot the drawing extents instead: script `FILEDIA 0 / TILEMODE 0 / ZOOM E / -PLOT Y <blank> 'DWG To PDF.pc3' 'ISO full bleed A3 (420.00 x 297.00 MM)' M L N E F C Y . Y N N N <out.pdf> N Y / QUIT Y` (plot area = Extents, fit). Use the same extents plot of the user's finished sheet for a like-for-like comparison.
- Views running off the sheet: first compare the view list with the contract. Factory starting styles carry extra views (column style: top view, end-plate view) that make the vertical stack taller than the frame; trim `DetailStyle.[Number of items]`/`Request1..n` to the contracted views (set unused RequestN to 0, leave the view rows in place) before touching placement. If the stack fits but still overflows with empty space below, the remaining cause is placement (start position), not size.
- Do not plan to fix orientation by swapping a modelled column's start/end: Live Link `beammod.sync` refuses because welded/bolted connectors cannot follow, so orientation of finished models must come from the style (or a bare test column in a blank drawing).
- Model-role / factory rule fit: roles live in `DetObjQualifierSetItem.ModelRole` per qualifier set. Endplate/Baseplate/Coverplate are caught by `EndPlate, Roles` (10) and excluded from `AttParts no EndPlates` (64/76), so a chain that must include cap/base plates needs `AttParts` (4). A plate set to `Plate` is not caught by Fin Plate (20506) or Gusset (108) rules.
