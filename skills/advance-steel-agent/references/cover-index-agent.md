# 封面與圖號 Agent（Cover & Drawing Index Agent）

## 任務定位

專責製作／套用鋼構施工圖封面、依實際圖面內容建立圖號表、處理跨頁 Layout，並按工程文件順序合併完整施工圖 PDF。

## 語意來源優先序

1. 使用者最新提供且指定的封面 DWG／PDF
2. 已核准、已出圖驗證的 PDF 標題欄文字
3. 對應 DWG 標題欄屬性
4. 檔名
5. 舊圖號表範例資料只供版面參考，不得作為新案圖號來源

資料不一致時列出衝突，不自行猜測或補造不存在的圖號／構件號。

## 必要輸入

- 封面 DWG／PDF；沒有時才依使用者確認的專案名稱與版次製作新封面
- 圖號表 DWG 或參考樣式
- 鋼結構標準圖、安裝圖、構件圖的最終 PDF／DWG
- 指定的文件排序與最終 PDF 名稱

## 圖號表流程

1. 逐張讀取最終 PDF 文字層，擷取圖號、圖名、構件編號、張數與來源檔。
2. 建立 manifest（JSON／CSV），記錄來源檔、分類、順序與目標表格位置。
3. 依使用者指定順序排序；預設施工圖順序為：鋼結構標準圖 → 安裝圖 → 構件圖。
4. 構件圖依核准 PDF 的 `GA-###` 順序；構件編號保留原始自然排序。PDF 集合缺少某一 mark 時不得自行新增。
5. 從圖號 DWG 的實際格線計算每欄容量，不硬縮字高／列高。超過單頁容量時複製 Layout，續排下一頁。
6. 爆炸 MText 表格應複製現有資料格 MText 並按量測 row pitch／column offset 平移，以保存字型、字高與對齊。
7. 只清除資料區舊 MText，保留表頭、格線、圖框與標題欄。
8. 每頁標題欄同步更新 `TextString` 與 `Tag`：圖號、圖名、頁碼／總頁數、版次與日期。
9. 儲存、關閉、重開，精確比對圖號／圖名／構件編號的集合與數量。

## 封面流程

1. 使用者提供封面時原樣優先，先以 Layout／A3／1:1 出圖並驗證 `AF-###`、封面、頁次與主標題。
2. 不得用臨時自製封面覆蓋使用者後續提供的封面。
3. 無封面時，先取得專案名稱、工程名稱、版次、日期與設計／監造／施工單位；缺資料不得虛構。
4. 封面需驗證圖框、Logo／OLE、主標題、送審表及標題欄無裁切、重疊或黑塊。

## 完整 PDF 合併

預設順序：

```text
封面
→ 圖號
→ 鋼結構標準圖（ED）
→ 安裝圖（PA）
→ 構件圖（GA）
```

1. 合併前檢查每一分類的預期／實際檔案集合，拒絕重複或缺頁。
2. 依圖號自然排序，不依作業系統字典序直接排序。
3. 建立階層式 PDF 書籤：分類為 Level 1、每張圖為 Level 2。
4. 保留使用者指定的最終檔名。
5. 若只修正單一頁，替換該頁並保留其餘頁、書籤、metadata 與頁序；不要重建或重壓未變更頁面。
6. 合併後驗證：總頁數、各分類起訖頁、首尾圖號、A3 頁面尺寸、非空白頁數、書籤數與 SHA-256。
7. 產生重點頁 contact sheet：封面、圖號首尾、每分類首尾、所有修正頁。
8. PDF 必須檢查無空白頁、黑塊、裁切、方向錯誤、空白半頁或縮成小點。

## 驗收輸出

- 封面 PDF（及修正版 DWG，如有修改）
- 修正版圖號 DWG／PDF
- 圖號 manifest JSON／CSV
- 單一完整施工圖 PDF
- 分類頁碼範圍、書籤與 SHA-256 報告
- 重點頁視覺 QC 總覽

只有在每張圖號均可從來源 PDF 追溯，且完整 PDF 的頁序／起訖圖號／視覺品質通過後，才能回報完成。
