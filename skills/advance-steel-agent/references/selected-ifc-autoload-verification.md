# Selected IFC plugin installation and AutoLoader verification

- When the user authorizes exporting unsaved model changes, remove DBMOD-zero gates at every pre/post-export call site, not just the initial policy. Keep no-save behavior, explicit selection/exclusion rules and no-overwrite publishing. Record DBMOD as observation and identify saved-file SHA as disk bytes only; it cannot fingerprint RAM changes. Prove in-memory semantics with a fresh full fixture: export baseline, deliberately change a native property and displayed color without saving, export dirty state, read actual IFC properties/styles, compare geometry and disk hashes. Distinguish this from installed AutoLoader/Ribbon acceptance and explicitly document whether never-saved unnamed drawings remain unsupported.
- Use `wait_until(..., operation=...)` for the shared waiting helper and `retry_busy_com(..., description=...)` for COM retries; these keywords are different. If a driver fails after SendCommand, inspect exact output/state before retrying so a completed mutation is not replayed.

- Resolve selected `ASTHOLEPLATE` through the explicitly selected AtomicElement's `GetFeatures(false)` and the feature's `DatabaseManager.GetReprId`. Do not assume features appear in the top-level GetModelObjectIds inventory, equate native and representation handles, or silently add unselected hosts. Reject missing/ambiguous ownership. A feature pattern can contain multiple physical holes, so verify actual IFC openings and geometry against a host-only baseline rather than equating feature count with opening count.
- Preserve native-host mapping precedence: a representation mapped to an AS host must not be discarded solely by DXF type. Where the user explicitly requests automatic non-native filtering, skip ordinary unmapped entities (including 3DSOLID) without a prompt; report counts and persist handles/types. Do not misclassify unresolved AST or proxy objects as proven non-native. Test mixed selection against a native-only baseline and verify foreign-only/empty selections publish nothing. Prefer existing non-native entities in a full read-only copy; synthetic geometry creation is unnecessary if a supported read-only fixture already covers the behavior. For a confirmation-based policy instead, test default-cancel and explicit-approval paths; do not impose that older policy over a newer explicit user request.
- When shipping a new integrated payload, allow an installed predecessor receipt only via an embedded exact previous-package-digest plus bundle-file-map allowlist. Knowing the old file inventory alone is insufficient if receipt validation pins the current package hash. Exercise the actual old EXE install followed by new EXE upgrade and verify in an isolated Windows sandbox; do not weaken unknown-receipt refusal.

- Do not equate a successfully created fallback Ribbon button with native-resource readiness. Keep bounded, throttled UI Idle discovery until the native icon is available; preserve the existing command handler during retries, and detach on success, deadline, or termination.
- Do not assume first UI Idle means native Advance Steel Ribbon resources are ready. A documentless startup followed by delayed first-document opening can exhaust a first-idle timeout before native IFC resources exist; a later native button can appear while the custom button remains fallback. Gate discovery on meaningful host readiness or rearm a bounded window on relevant document/resource lifecycle events, then verify the actual cold-start pixels without modifying the icon through the diagnostic. Policy tests alone do not establish this behavior.

- Separate package integrity, actual user-profile installation, restart AutoLoader inspection, and real IFC export. A passing installer Verify action does not prove AutoLoader behavior; an AutoLoader pass does not rerun geometry acceptance.
- Close only explicitly authorized documents, refusing unexpected documents or unapproved unsaved changes; use normal Close/Quit, never global process termination. Record exact paths and process exit.
- Prefer starting Advance Steel without a DWG argument, then opening a complete isolated test copy read-only through the shared AcadSession. Command-line opening of a model may leave DBMOD nonzero. Check actual DBMOD after startup, not merely quiescent/idle; preserve newly dirty documents rather than inferring discard permission from earlier authorization for a different copy.
- A read-only AutoLoader diagnostic must not NETLOAD the target plugin or reference it in a way that could load it. Inspect the already loaded assembly location and hash against the installed ApplicationPlugins payload, plus the real Ribbon handler and button properties. Loading a separate diagnostic assembly is not loading the target, but disclose this distinction.
- Verify the icon variant on cold startup separately. Advance Steel native Ribbon resources may not exist when the plugin initializes, so a valid fallback can appear even when a live-session preview used the native icon. Do not claim the native icon was reused based only on ShowImage=true.
- Verify installed payload hashes after deployment and retain source disk hashes, DBMOD, and open-document states. Process-scoped RemoteSigned does not justify permanent execution-policy edits; verify the ordinary policy separately.
- Use an OS-safe tempfile with a hermes-verify- prefix for requested ad-hoc checks, remove it afterward, and label the result ad-hoc rather than suite green. retry_busy_com requires an explicit description keyword.
