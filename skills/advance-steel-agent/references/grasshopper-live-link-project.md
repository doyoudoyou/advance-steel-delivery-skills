# Grasshopper <-> Advance Steel Live Link (plugin project notes)

Use when planning or building a Rhino/Grasshopper live link for Advance Steel (Tekla Live Link equivalent, Dynamo-for-AS naming).

## Project context
- Repo: private `<owner>/Advance-Steel-Live-Link`, local clone `<WORKSPACE>/Advance-Steel-Live-Link`. Read `docs/` (ROADMAP, VERSION-MATRIX, PHASE-*-RESULT, adr/) before continuing; they hold the measured state and the list of unverified items.
- User decisions: AS2027 only; no rebar; Drawing Link out of v0.1.0 but developed after it (roadmap v2 `docs/DRAWING-LINK-ROADMAP.md`, phase results `docs/DRAWING-LINK-D*-RESULT.md`; D1 camera components are in the plugin under GH subcategory Drawing); repo stays private, `LICENSE` = "Private, all rights reserved"; debug probes excluded from release builds; all component icons are original code-drawn designs (no vendor art). Progress / release gate list: `docs/V0.1.0-CHECKLIST.md`.
- Working rhythm the user expects: one roadmap item per turn, real host test, a `docs/PHASE-x.y-RESULT.md` with an explicit "unverified / limits" section, commit + push, then propose the next item (offer two concrete options). User replies "繼續/下一步" or a number to advance.
- `docs/STATUS.md` is the single overview: label each component with its verification level (script / canvas by the user / visual by the user), keep a known-issues table, and when a feature once declared infeasible later works, move it to a "corrections" table stating the real cause instead of silently deleting the old claim. Refresh it (and NAMING-AUDIT) after every few phases; they drift quickly.
- When a result is shown to the user, end with what is verified, what is not, and cleanup state (which PIDs you started are still open, test plugin folder removed, user's own library untouched).
- Keep ONE consolidated open-items list (`docs/BACKLOG.md`) instead of letting "unverified" sections scatter: harvest every `PHASE-*` "未驗證" section with a script (regex on the heading, dump to a file), group by area, give each row a "how to close" tag (script = agent alone / canvas = user ~3 min / probe = may prove AS cannot / decision = user chooses), and keep a "resolved, removed" table naming where each closed item was proven. When an item is closed, delete its BACKLOG row, add it to the resolved table, and edit the original phase doc's line to point to the proof. STATUS and USER-GUIDE link to BACKLOG rather than carrying their own todo lists. Next-step offers then come straight from the tags: batch all "script" rows into one test run, batch "canvas" rows into one user session.
- Several identical short replies in one message (e.g. "1" five times) are one choice, not five turns of work.
- Before offering "investigate unexplained X" as a next step, grep all `docs/` for X (and the BACKLOG row's source phase): a later phase may already have explained it while BACKLOG was never updated. If so, move the row to resolved (noting it was stale) instead of re-probing, and admit the wrong offer.
- Unexplained-reading investigations: one `debug.*` probe with a labelled matrix varying ONE quantity at a time (vertex count, size, thickness / radius, angle, orientation), log the ratio of the discrepancy to each candidate driver (perimeter×t, n, t; effR − R); the driver whose ratio is constant across the matrix is the cause. Then update the component description, the original phase doc line, BACKLOG and USER-GUIDE known issues.

## Architecture facts (measured)
- AS2027 runs on .NET 10; AS managed DLLs in `C:\Program Files\Autodesk\AutoCAD 2027\ADVS\`. Rhino 8.24 loads a `net8.0-windows` `.gha`. Contracts project is netstandard2.0 (JSON DTOs only).
- AS API only runs inside the AutoCAD process; Grasshopper inside Rhino -> `.gha` client + in-process AS server over Named Pipe, line-delimited JSON-RPC 2.0.
- Link tag = XData `ASLL_LINK` JSON on each AS object; ComponentId = GH InstanceGuid ("N"). Update = delete + recreate (handle changes). Hash-diff so unchanged items keep their handle.
- Main-thread dispatch is hybrid: each job is both `Post`ed to the UI SynchronizationContext and queued for `Application.Idle`; `Interlocked.Exchange` lets the first run it. Measured to keep working while a command waits for input (`CMDNAMES=LINE`) and with the OPTIONS modal dialog open (Idle stops firing, the Post path serves); other dialog types untested. Check `git log` / the ADR before claiming a doc is stale.

## AS API pitfalls
- In script/`/b` launches the AS document is not registered until `Application.Idle` (~20 s); `WriteToDb()` before that returns a null ObjectId. Treat a null ObjectId as failure and gate RPC on readiness.
- `ProfileName.ToString()` returns the type name; use `.Name`. Section string is `Type#@§@#Size`. Explicit section strings persist exactly across save/reopen on GBR, USA and INT templates; the template default (`ProfilesManager.GetProfTypeAsDefault`) differs per template and can throw NullReference in a script-launched AS (beam then has no section, volume 0), so never rely on it. AS accepts a nonexistent section string and builds a broken beam: keep the server-side `unknown section` pre-check (`GetProfileType` null or `Dummy`).
- Validate the whole batch first, write inside one `DocumentAccess`, and `DiscardAllChanges()` if any item fails (all-or-nothing).
- Composite/welded beams (`BeamTapered(start,end,zVect,h1,h2,tw)`): `SysLength` reads right but the body is EMPTY (Volume 0, weight 0, `GetModeler().Volume` 0, zero vertices, empty `ProfName`). `SysLength` alone proves nothing; the tapered component is NOT verified and must not ship until Volume/vertices are non-zero AND segment heights match the inputs. Missing step: `beam.CreateComponents()` then WriteToDb builds 5 sub-plates and gives non-zero Volume/weight; but `GetSegmentsData` then reads h=250/400/400/300 for inputs 500->250, so the input-to-geometry mapping is still unknown. Never read `CompoundClassName`/`CompoundTypeName` (crashes AS). The component is hidden via `GH_Exposure.hidden` until resolved (old files still load). Always verify a new object kind with a geometry read (Volume or vertex bbox), never only a length/handle read.
- Bolt patterns (`FinitRectScrewBoltPattern(ptRef, ptRef2, vX, vY)`): the two points are reference-rectangle corners; Nx/Ny/Dx/Dy are then re-laid around the rectangle CENTRE. With N=1 in a direction AS keeps a 1 mm rectangle, so compare that direction by centre only, not spacing/corners. Standalone patterns do not cut parts; attaching needs the connection API.
- Plate holes (Dynamo `PlateHoles.cs` order): `h = new ConnectionHolePlate(plate, cs)` -> `h.Arranger = new Autodesk.AdvanceSteel.Arrangement.RectangularArranger(new Matrix2d(), dx, dy, nx, ny)` -> `h.SetHoleType(eHoleType kHole=1)` -> `h.Hole = new Contours.Hole(d)` -> `plate.AddFeature(h)` -> `plate.WriteToDb()`; never WriteToDb the feature alone (leaves 0 features). Read-back that works: `NumberOfHoles` = nx*ny; hole-wall vertices in `GetModeler(kDetailed)` / `kCollision` have radius d/2 at the input centre. `plate.Volume` and kNormal/kHull bodies ignore holes. Hole CS placement (measured, confirmed visually): AS cuts from the CS origin towards CS -Z, so put the origin on the plate face on the `PlateNormal` side (pick the face from `GetUpperAndLowerPlane` with the larger dot with the normal; project the user origin onto it) with Z = PlateNormal and X = user X projected into the plate. Origin on the bottom face with +Z gives only a 0.5 mm mark. The default feature `Depth` is 50 mm, so plates thicker than ~50 are only partly cut: set `Depth = Thickness + 1` before AddFeature. Verify each hole by the span along the plate normal of kDetailed vertices whose in-plane distance to the hole axis (`GetElementOrigins`) equals d/2 (must equal thickness); do not use removed volume (AS draws holes as 8- or 16-gons, ~97% of pi r^2 t, and a half-depth cut can pass a loose volume threshold). `RectangularArranger` lays the nx*ny grid centred on the CS origin. A hole centred on the plate edge cuts a half-circle notch with full-depth walls (accept it); a hole fully outside gives depth 0 (reject + roll back). Hole features are found like copes: plate `GetFeatures(false)` -> Open -> `ConnectionHolePlate` with our XData tag; update = `DelFeature` + WriteToDb; include them in component delete/bake. eHoleType: kHole=1, kSlottedHole=2, kCounterSunk=3, kBlindHole=4, kThreadHole=5, kSunkBolt=6, kPunchMark=7. Never call `GetNumberOfConnectedHoles` on a plate with attached holes (crashes AS).
- Typed holes (same `ConnectionHolePlate`, `SetHoleType(code)` then `Hole = ...`), measured on t20:
  - Slot: `new Contours.SlottedHole(d, slotLength, eDirection)`; slotLength = OVERALL length incl. both round ends. eDirection kArcAlong=0/kXAxis=1/kYAxis=2: in a rect arranger kArcAlong cuts NOTHING (allow only 1/2); in a circle arranger slots run along the circle whatever the value.
  - Blind/thread: `new Contours.ExtendedHole(type)` + `Diameter`, `SunkDepth` = depth from the face (`Depth` has no effect); a thread hole's body is identical to a blind hole (HeadDiameter = tapping size, IsTappingRight, Alpha_e are stored only).
  - Sunk bolt (kSunkBolt=6): through bore + cone at the face; `HeadDiameter` = countersink dia, `SunkDepth` = cone depth, `Alpha_e` is in RADIANS (π/4 gives an exact 45° cone; Dynamo's hard-coded 45 gives a malformed shape). Expose degrees in GH and convert.
  - kCounterSunk (3) cut no material in six parameter combinations: do not ship `CSunkHoleByCS`; use kSunkBolt for countersinks.
  - Punch mark (7): counted in `NumberOfHoles`, no body cut; verify count + type only.
  - AS accepts invalid combos silently: blind depth ≥ t becomes a through hole; depth 0, sunk dia ≤ d, slot length ≤ d cut nothing; sunk depth ≥ t malforms. Pre-reject all of these, compare plate thickness server-side.
  - CS z direction decides the face (CS on the bottom face with z down cuts from below).
  - Per-type body read-back: hole/slot ends wall span = t; blind/thread wall from the face with span = depth; sunk bore reaches the far face and a wall at sunkDia/2 touches the face; rect-slot in-plane half-extents. Overlap checks must use the footprint (slot length, countersink dia), not the bore diameter. d18 holes are octagons: area 229.1 for volume expectations.
- Circular hole pattern: same feature with `new Autodesk.AdvanceSteel.Arrangement.CircleArranger(new Matrix2d(), radius, n)`; share one `holes.sync` with a `Pattern` (rect|circle) field and a distinct hash prefix so existing rect holes do not rebuild. Read the hole count back from `Arranger.NumberOfElements`: `CircleArranger.Nx` reads 0, so an Nx check rolls back every (correctly cut) pattern. Reject overlap before writing with neighbour distance `2R·sin(pi/n) <= d`. Holes lie at exactly R from the projected origin, 360/n apart; the first hole is at 30° from the plane X axis for n=6 (rotates with X; origin of the offset unverified), so tests should check radius and spacing, not absolute angles. Rect and circle features on one plate coexist and delete independently.
- When a geometry read stays ambiguous after two probes, stop probing and ask the user for a one-minute visual check in a left-open AS (state exactly what to look at) instead of building the component on an unproven assumption. Prepare it with a debug RPC that sends a fixed view command (`_.-VIEW _SWISO _.ZOOM _E _.VSCURRENT _Conceptual`), lay test parts out at distinct Y offsets, and tell the user which part is which. A negative visual answer usually means a wrong placement/orientation assumption: next probe a small matrix of variants (origin on each face x +Z/-Z) and read the result per variant.
- Measure the target quantity directly (e.g. cut depth from vertex span) instead of a proxy with a loose threshold (volume >= 80%); the proxy hid a 50 mm depth cap on a 60 mm plate.
- Bolt connect: `BoltPattern.Connect(FilerObject[] parts, AtomicElement.eAssemblyLocation)` (members kOnSite=0, kSiteDrill=1, kInShop=2) then WriteToDb bolt AND parts. Verify holes with `part.NumberOfHoles` (delta must equal Nx*Ny); `Volume` never reflects holes. A bolt grid fully outside the part connects silently with 0 holes, and a grid HALF off the part still adds all Nx*Ny holes, so the hole-count delta alone does not prove placement: before writing, require every bolt/anchor/stud centre to lie on the part, then also check the hole delta, and roll back the batch on either failure. For PLATES test against the contour polygon, not the bounding box: project each point onto the plate definition plane (`GetDefinitionPlaneCS` + `GetBaseContourPolygon(0, out pts)`), accept if inside the polygon or within 1 mm of an edge (shared helper `PartFootprint.FirstOutside`, used by every connector sync). A bbox check lets through points inside the box of a rotated/non-rectangular plate but off it, and AS then connects silently (0 holes or still cuts some). Outline/bbox alone is not enough: also require that a line through each point along the connector direction (plate normal; else ux × uy) hits the part's body, `part.GetModeler(kNormal).IntersectWith(new Line3d(pt, dir), out Point3d[] hits)` with hits > 0, retrying at ±1 mm in-plane for the edge tolerance; this rejects plate inner openings, the air beside a flange, cope zones and the empty part of a diagonal beam's bbox (kNormal = kDetailed here). For connectors WITHOUT a direction (welds) use `ModelerBody.Contains(pt)` at the point or ±1 mm along ±X/±Y/±Z: it returns true for points on a face and false over plate openings, beside flanges and in a diagonal beam's empty bbox. Never use `ClosestPointTo` for this: it ignores plate openings (distance 0 over a hole). Skip the body test (`bodyCheck: false`) for points that already have holes (existing connected bolts, PlateHoles when re-checking a modified plate contour): the line through a drilled hole misses the body. Bolts/anchors off the body were already caught by the hole-count read-back (AS cuts 0 holes); the real loophole of an outline-only check is connectors WITHOUT holes (shear studs), so put the negative cases on studs. Hole dia = screw dia + HoleTolerance (2). `RemoveConnectedObjects` removes the holes. After Connect AS shifts the pattern along the part normal by the part thickness, so compare only in-plane position when connected.
- Inside the server, `ObjectId` is ambiguous between AutoCAD and AS. AS APIs (`DatabaseManager.GetModelObjectIds(out ...)`, `Open`) need `Autodesk.AdvanceSteel.CADLink.Database.ObjectId`. `AtomicElement` lives in `Autodesk.AdvanceSteel.ConstructionTypes`. AS model objects have no `.ObjectId` property; keep the id returned by `WriteToDb()`. In debug probes, write these types fully qualified so the first build passes (also `Autodesk.AdvanceSteel.ConstructionTypes.FeatureObject` in lambda/Func signatures).
- Enum member names are not guessable (no `kShop`): list them by reflection (`Enum.GetNames`) in a debug probe.
- Rhino Python GH tests: after changing PersistentData also call `param.ExpireSolution(False)`, otherwise a later solve can reuse stale inputs.
- Unknown API behaviour: write a `debug.*` RPC probe that logs each step to a trace file in %TEMP% BEFORE the risky call, so an AS crash still shows where it stopped (empty pipe reply = process died).
- Bolt/part `connectTo` uses AS handle strings from upstream components. Verified: connecting a beam (holes counted via NumberOfHoles) and reopen persistence (save with `doc.save`, then open the DWG in a fresh AS process and `model.list`). Unverified: handle churn on upstream rebuild.
- Beam plane cut (BeamShortening), Dynamo `BeamPlaneCut.cs` order, verified straight + oblique and visually confirmed: `f = new BeamShortening()` (no args) -> `beam.AddFeature(f)` -> `f.Set(point, normal)` (2-arg) -> `beam.WriteToDb()`. Never use the 3-arg `Set(p, n, end)` before AddFeature or assign `AngleOnZ` directly: both crash AS. The side the normal points to is REMOVED; AS derives `End` itself and reads the obliquity back as `AngleOnY` (tilt in XZ) / `AngleOnZ` (tilt in XY). `SysLength` never changes: verify with `beam.Volume` (proportional to kept length) and kNormal body vertices (none may lie > 0.01 mm on the normal side; AS leaves the cut face 0.001 mm inside, e.g. 200.001). Reject before writing a plane (almost) parallel to the beam axis (|n·axis| < 0.01), and after writing: no volume removed (plane misses) or volume 0 (whole beam removed). Two cuts on one beam (both ends) work. Length mode (Dynamo `ByStartValue`/`ByEndValue`) reuses the same sync: compute the point on the system line from `GetPointAtStart(0)`/`GetPointAtEnd(0)` (start: at L along the axis with normal = -axis; end: at axisLen-L with normal = +axis), reject L <= 0 or L >= axis length before writing, and give it a distinct hash prefix. Test it on a beam drawn backwards (start is the far end), a plan-diagonal beam and a sloped beam (cut must read back AngleOnY/AngleOnZ = 0), not only on +X beams. `GetFeatures()` returns ObjectIds: `DatabaseManager.Open` them before type tests, and filter by the concrete feature class (`BeamNotch`, `BeamShortening`, `ConnectionHolePlate`): a sync that accepts any tagged `FeatureObject` will pick up another component's features on the same part.
- Cope `new BeamNotch2Ortho(eEnd, eSide, length, depth)` + AddFeature + WriteToDb works. For BEAMS `beam.Volume` (= `GetModeler(eBodyContext).Volume`) does drop after a cut, so use it as the verification read (unlike plates, where Volume ignores holes). Measured: `depth` is measured from the section centreline, read back `ReferenceDepth = depth + sectionHeight/2`; removed volume scales linearly with length. Volume cannot tell kStart from kEnd or kUpper from kLower on a symmetric section, so verify end/side by counting `GetModeler(ctx).Vertices` near each beam end per z-half (cut adds 4 vertices where it lands; place each test beam at a distinct Y offset, not Z, or the counts mix). Measured: kStart cuts the x=0 end, kEnd the far end; side is BEAM-LOCAL: kUpper cuts the half opposite the beam ZAxis (flips when ZAxis flips). Cope features carry an XData tag fine but are NOT in `GetModelObjectIds`: find them via each beam's `GetFeatures(false)` (ObjectIds -> Open); update = `beam.DelFeature(f)` + WriteToDb, which restores the volume exactly. Enums: eEnd kMid=0,kStart=1,kEnd=2,kNoEnd=3; eSide kUpper=1,kLower=2; never take `GetValue(0)` (that gave kMid). Modeler types need a reference to `ASModelerMgd.dll`; `eBodyContext` is `Autodesk.AdvanceSteel.Modeler.BodyContext.eBodyContext` (kNormal=0, kDetailed=1, ...), not nested in AtomicElement. `Beam.GetWeight` needs an int arg.
- Shared server core: one `SyncCore.Run` (XData tag, hash-diff, delete-missing, per-item read-back `Verify`, DiscardAllChanges on any failure) reused by every new object kind keeps behaviour identical across components; add a kind by supplying create + verify lambdas only.
- Group risky API calls into SEPARATE debug probes (one risky call each). A crash loses all later results in the same probe.
- In a debug probe, read object state inside its own `using (doc.LockDocument()) using (new DocumentAccess(null, true))`: `DatabaseManager.Open` outside any DocumentAccess returns null even for objects that exist, so every row reads `Open=null` and looks like deletion. If the "before" row is already null, the probe is wrong, not the model.
- Bake of a FEATURE (cut/hole/cope) only drops the feature's tag; the GH component then re-solves (menu calls ExpireSolution) and tries to recreate the same feature. Each feature kind needs a check that REJECTS the duplicate, otherwise it stacks silently: cuts and copes are caught by "no material removed", but a hole's through-check (wall span = thickness) still passes because the baked hole's walls already exist, so a second identical hole set was written (`NumberOfHoles` 10 -> 14; invisible on screen). Fix: after writing a hole feature, compare every new hole axis (`GetElementOrigins`, projected onto the plate plane) with every OTHER `ConnectionHolePlate` on the plate, tagged or not, and roll back when centre distance < r1 + r2; the component's own update is unaffected because its old feature is deleted first. For any new feature kind, write a test: create -> `BakeToAs()` -> re-solve -> host's feature/hole count and volume unchanged and exactly one error; also reject a new feature that collides with an UNLINKED (baked/manual) one, and say "linked"/"unlinked" in the message.
- Feature components (cope, plane cuts, holes, corner cuts) override `LockAfterBake => true`: the right-click menu calls `BakeFromMenu()`, which bakes, clears runtime messages, sets `Locked = true` and `Message = "baked N, locked"`, so the canvas shows no red error and later input changes never reach AS. Host components (beam/plate/bolt) stay unlocked (Tekla behaviour: a new linked copy is created). Test via `BakeFromMenu()` (the same path as the menu) and in the harness skip `CollectData/ComputeData` when `comp.Locked`, as GH does. `BakeFromMenu` ends with `ExpireSolution(true)`, which in an enabled `GH_Document` already re-solves: a host's new copy exists right after the call and the next solve reads `unchanged`, so assert "new handle, old object untagged", not `created`.
- A baked feature lives on the old host: when GH rebuilds that host (slider drag), the baked feature is deleted with it (confirmed on canvas). To keep a feature, bake its host too.
- Orphan beam (closed as known / unreproduced, docs PHASE-3.12): once on a real canvas, Bake a plane cut then drag the host's slider left the OLD beam untagged in the model. Every reproduction passed: probes (bake + failed re-solves + rebuild, failing feature sync after rebuild, DelFromDb then DiscardAllChanges, tag then rollback), a second canvas run, and `tests/gh/orphan_stress_test.py` (0/1/2 drags before Bake × straight/angled baked cut × a mid-drag cut that misses; beams == tagged at all 84 steps). Do not re-chase it or offer it as a next step; if it recurs, ask for the last lines of `%TEMP%\asll_spike.log` (server `TRACE`: component id, idx, deleted/created handle, ROLLBACK, bake untag) to find the step that left the handle. Script coverage does not include real GH solve timing, so still avoid claiming Bake+rebuild is proven safe on canvas.
- Plate corner cut (Dynamo `PlateVertexCut`): `PlateFeatVertFillet(short contour, short vertex, l1, l2)` = straight chamfer; `(contour, vertex, r, eFilletTypes)` = fillet (kFilletConvex=0, kFilletConcav=1, kFilletStraight=2). The radius-only 3-arg ctor silently makes a 45° chamfer (r x r), so always pass the type. Then `plate.AddFeature(f)` + `plate.WriteToDb()`; no crash in any variant. `VertexIndex` = order of the polygon vertices as given in GH (verified on a clockwise pentagon with an odd start; `GetBaseContourPolygon(0, out Point3d[])` returns the same order), contour 0 = outer. `length1` runs along the edge towards the NEXT vertex. Unlike holes, `plate.Volume` DOES drop (chamfer = ½·l1·l2·sin θ·t exactly; fillets are 4-segment arcs: R40 convex 3754.1, concave 12245.9 on t10). Verify: type/vertex/lengths read back, corner vertex gone from the kNormal body (in-plane distance), other corners still present, removed volume. Pre-checks: corner in range, convex corner only (Newell-normal turn test; reflex untested), chamfer/tangent length (convex: r/tan(θ/2)) shorter than the adjacent edges, no other `PlateFeatVertFillet` on that corner (tagged or not), no duplicate corner in one batch.
- Plate polygon cut (Dynamo `PlatePolycut`), two AS classes, both no-crash:
  - `PlateContourNotch(plate, 0, Polyline3d contourWCS, normalWCS, lengthVec)` takes WORLD coordinates (independent of the plate origin) and may cross the plate edge (cuts only the part inside → notch). Best fit for a GH closed curve (`FromPolyCurve`). Build the polyline with `new Polyline3d(pts, new double[n], true, normal, false, 1e-6, false, false)`.
  - `PlateFeatContour(Matrix2d, length, width)` / `(Matrix2d, radius)` (Dynamo `ByLengthAndWidth`/`ByRadius`) uses PLATE-LOCAL coordinates whose origin is the plate's FIRST VERTEX (`GetDefinitionPlaneCS()`), not the plane origin passed to the Plate ctor; its X does NOT follow the first edge (a horizontal plate rotated 30° still has X = world X). The shape is centred on the matrix origin, length along local x. `Offset` works for rects AND circles (circle box = 2R): corner 0 (−1,1) → shape extends +L +W from the insert point, 1 (1,1) → −L +W, 2 (1,−1) → −L −W, 3 (−1,−1) → +L −W. Verified on tilted plates (30° about X, vertical XZ, vertical YZ): offsets land in the frame of the first edge / last edge from the first vertex; a plate normal to world X gets local X = world +Y. A shape landing off the plate removes nothing with no error: pre-check that all 4 box corners are inside the plate contour (in local coords) and point users to `FromPolyCurve` for edge notches. Convert WCS → local explicitly; never assume.
  - Circles (plate and beam) are inscribed n-gons whose n AS picks by radius (r40 → 16, r50 → 16, r60 → 32): never hard-code 16 in an expected area. Read n from the distinct angles of the NEW body vertices, require each new vertex on the circle (0.01 mm; off-circle vertices mean an overlap with an existing cut), then expect `n/2·sin(2π/n)·r²·t`.
  - Verify the cut position with the feature's own contour (`PlateFeatContour.GetContourPolygon(0)` / `BeamMultiContourNotch.getContourPolygon(out pts)`): it returns the box corners (4 points, also for circles), compare to the expected box at 1e-3 mm.
  - `plate.Volume` DOES drop for both, so verify by volume. AS offsets the notch outline 0.001 mm outward, so it removes exactly `perimeter × t × 0.001` mm³ more than area·t (measured on 10 shapes/thicknesses): tolerance `1e-4·expected + 5` absorbs it; for an exact check add the perimeter term.
  - Server recipe that passed: project the points onto the plate plane in a local (u,v) frame (first contour vertex + first edge + normal), reject if they spread > 0.01 mm along the normal, force CCW about the normal so GH curve direction does not matter; pre-reject < 3 points, zero-length edge, self-intersection (segment test on non-adjacent edges), zero area, fully outside, enclosing the whole plate, touching the edge only, lengthVec zero/parallel to the normal. Expected removed volume: inside → area·t; crossing a CONVEX plate → Sutherland–Hodgman clip area·t; crossing a non-convex plate → only bounds-check 0 < removed ≤ area·t (log it). removed 0 → reject "no material" (already cut, e.g. baked); mismatch → reject "overlaps an existing cut/hole/corner cut". Accept only polylines in GH (`TryGetPolyline`); arcs untested, reject with a hint to use Polygon. Corner features/polycuts have no repr: `SelectionHandles` should return the plate handles.
- Beam polygon cut (Dynamo `BeamPolycut`, all six nodes): `new BeamMultiContourNotch(beam, eEnd, Polyline3d contourWCS | (center, normal, xvec, length, width) | (center, normal, xvec, radius), normalWCS, xvec)` + `beam.AddFeature` + `beam.WriteToDb()`; no crash. The cut is a PRISM THROUGH THE WHOLE BEAM along the normal (a curve on the top face severs both flanges and the web; a curve 500 mm beside the beam cuts the same), and the eEnd argument has no effect (pass kStart). `beam.Volume` drops (web rect 200x100 on UB254x146x31 = 120003.6). Exact expected volume through an I-section along an arbitrary normal is not computable, so verify: removed > 0 (else reject "no material": misses or already cut), removed ≤ polygon area × beam depth along the normal, and every NEW kNormal vertex lies inside the polygon prism (in-plane, 0.05 mm). Consequence: a partial overlap with an existing cut is accepted (only the new part is cut), unlike plate cuts where the exact clipped volume rejects it — document this. Use the polygon's own Newell normal as the cut direction; when the net area is 0 (symmetric bow tie) fall back to the cross product of two non-parallel edges so the self-intersection check reports the real cause instead of "collinear". Offset rule for the rect/circle ctors matches plate cuts, with beam-local y = normal × lengthVec (web cut normal +Y, lengthVec +X → y = −Z, so corner 3 "−W" goes UP); a normal-Z rect cuts through both flanges and the web. When two syncs share one AS feature class (polygon and rect/circle cuts are both `BeamMultiContourNotch`), add a kind field to the XData tag (`k`) so each sync's `Find` only takes its own, and check whether an older sync's DeleteAll/BakeAll already sweeps every tagged feature of that class for the component before adding a second delete path. Untested: ClipType (flange-only cuts), bent/poly beams, arcs.
- Connection objects (Dynamo `src/AdvanceSteelNodes/ConnectionObjects/*.cs`), all no-crash. They are OBJECTS, not features: use the shared `SyncCore`, Bake does not lock.
  - Welds: `new WeldPoint(pt, X, Y)` / `new WeldLine(Point3d[], X, Y) { IsClosed }` (closed: repeat the first point at the end, as Dynamo does) → `WriteToDb` → `Connect(FilerObject[] parts, eAssemblyLocation)`. No body, so verify connections, location, position, length. AS creates a DOUBLE fillet weld by default (`IsCombiWelding()` = kDoubleFilletWeld, upper + lower seam, `SeamDistance` 10): so `GetCenterPoint()` of a weld point is the input point minus 5 mm along the weld CS Z (midway between the seams; compare `center + 5`), and `WeldLine.Length` is the sum of both seams = 2× the polyline length (`SingleSeamLength` = 1×). AS does not check weld position: pre-require every weld point, weld-line vertex AND a point at most 50 mm apart along every segment to be within 1 mm of each connected part's BODY (`Contains` rule above); a bounding-box check accepted welds over plate openings, in a diagonal beam's bbox, and lines crossing an opening. Vertices + midpoint alone are not enough (a segment whose ends and midpoint are solid can still cross an opening off-centre). Openings narrower than the sample step can still slip between points.
  - `GetConnectedObjects(out ids, level)` lists the connected parts only at the object's OWN `AssemblyLocation` level (an on-site weld shows nothing under kInShop); always query with `obj.AssemblyLocation`. Unconnected welds read back kUnknown.
  - Anchors: `new AnchorPattern(centre, X, Y)`, set Nx/Ny/Dx/Dy (Dx/Dy only when N > 1) → WriteToDb → Connect(parts). Centred on the point, one hole per anchor in each part; bolt-style checks (in-part pre-check, hole delta, in-plane midpoints via `GetMidpoints`). Defaults M20 / "HOLDING DOWN BOLTS" / 4.6 / 300 long. `AnchorPattern.Length` is the ARRANGER (grid) length (reads Dx for a 2-wide grid), not the anchor: the anchor length is `ScrewLength` (= `AnchorUnfoldedLength`, = body z span, matches the part name "M20 x 300"). Before trusting a size property, check it against the body extent; a value that equals a grid spacing is a different property.
  - Anchor size (probe `debug.conndef`): `ScrewDiameter`, `ScrewLength`, `Standard`, `Grade` set BEFORE or AFTER WriteToDb/Connect all drive the body, part name and holes. Setting the diameter resets the length to an AS-chosen value that depends on the connected PART THICKNESS (M24 → 400 on t20 but 375 on t25; M30 → 450 on t20), so apply standard → grade → diameter → length last, and in tests assert only diameter + non-empty part name when no length is given (never a fixed table length). AS silently accepts a diameter/standard/grade not in its anchor table: `AnchorPartName` becomes empty and the length falls back to 40. Verify by requiring a non-empty part name plus read-back of each requested value; roll back otherwise. Overlap checks for circular anchors must use the requested diameter, not a hard-coded M20. Expose them as optional inputs added to the hash only when set (old .gh files unchanged).
  - Shear studs: `new Connector()` + `RectangularArranger(Matrix2d.kIdentity, dx, dy, nx, ny)` → WriteToDb → `Connect(part, cs)` (returns an auto WeldPoint; set its AssemblyLocation + WriteToDb) → THEN set `Diameter`/`Length` → WriteToDb. Values set before Connect (Dynamo's order) read back correctly but the body stays a fixed 75 mm / r 8 stud. Body = 16-gon prism (r = d/2) from the CS origin along CS Z; no head. Verify by body: height along the normal = Length (0.01), per-stud max in-plane vertex distance = d/2 (0.05), origins via `GetElementOrigins()`, connected part. Pre-check: every stud inside the part extent AND the CS origin on one of the part's faces along the stud direction (1 mm; catches studs floating above a flange); spacing > diameter. `Standard`/`Grade` accept any string and do not affect the body: do not expose. Catalog names (`EN ISO 13918 - SD 22 x 150`, `Nelson S3L`) were found by string-scraping `ProgramData/Autodesk/Advance Steel 2027/GBR/Steel/Data/AstorBase.mdf` (UTF-16 + ASCII regex) — a quick way to find valid AS catalog strings.
  - Circular variants reuse the rect syncs with a `Radius`/`Count` branch (Radius > 0 = circle): anchors = `AnchorPattern` + `ArrangerType = kCircle` + `NumberOfScrews`/`Radius` (default radius is 0 → all anchors stacked on the centre, so make radius required); studs = `Connector` + `CircleArranger(Matrix2d, r, n)`, size again only after Connect. Angles follow the circular-bolt rule; since positions are known only after write/Connect, read them back and roll back the batch if any lies off a part.
  - Deleting a Connector leaves its auto WeldPoint behind (one orphan per delete/update). The shared delete paths (`SyncCore.Run` update/drop, `SyncEngine` delete-all/by-handle) call `StudSync.DeleteWithOwnWelds`, which also deletes weld points connected only to that connector and at most one part. Any new object kind whose create step makes side objects needs the same: test "update/remove leaves no orphan" by counting those side objects (debug RPC listing them).
- Alternative-input Dynamo nodes (same AS object, different input form, e.g. `StraightBeam.ByLine`, `Plate.ByThreePoints`, `RectangularBoltPattern.ByRectangle`, `PlatePolycut.FromListCurves`): convert geometry GH-side into the EXISTING component's request DTO and call the existing RPC, so server validation/read-back are reused; add only test-support fields (bbox, bolt midpoints) to `model.list`. Probe placement rules first rather than copying Dynamo's labels:
  - Dynamo rectangular plate `Plate(plane, pt, L, W)` + `SetLengthAndWidth` + `Offset`: corner 0 (−1,1) → plate extends +X +Y from the point; 1 (1,1) → −X +Y; 2 (1,−1) → −X −Y; 3 (−1,−1) → +X −Y; other → centred. Dynamo's TL/TR/BR/BL labels do not match the actual position; document the real direction.
  - `Plane(pt, normal)` picks X by the AutoCAD arbitrary-axis rule (|n.x|,|n.y| < 1/64 → Y×n, else Z×n), measured for 5 normals; use it when only a normal is given.
  - `FinitRectScrewBoltPattern(c0, c2, X, Y)` with only Nx/Ny set: AS spaces bolts edge/(N−1) with corner bolts ON the rectangle corners; N=1 → centre.
  - PlateSync takes the thickness side from the polygon winding (Newell normal): order computed corners so the normal matches the intended side.
  - Joining user-supplied segments: `Curve.JoinCurves(segs, tol, preserveDirection: false)`; `true` does not flip reversed segments and the chain fails to close.
- Circular bolts `CircleScrewBoltPattern(centre, X, Y)`: defaults 6 bolts, r100, d20; set `NumberOfScrews`/`Radius`/`ScrewDiameter` before or after WriteToDb (both work). Bolts are evenly spaced and symmetric about CS Y (start angle chosen by AS): verify radius + equal angular gaps, not absolute angles. A circle fully off the part connects silently with 0 holes, so after WriteToDb read the real positions (`GetMidpoints`) and require each inside every part before Connect; reject overlap when `2r·sin(π/N) <= d`.
- Dynamo `BeamCope.ByRectangularRotatedCope` (`BeamNotchEx`): it only sets `XRotation` (kAroundNotch=0, kAroundBeam=1) and with all angles 0 both values give identical geometry, so it does not rotate; its depth base also differs from `BeamNotch2Ortho` (same depth 50: Ortho cuts to z −50, Ex to z +50). `XAngle`/`ZAngle`/`AxisAngle` (radians) each change geometry differently, meaning not established. Do not ship a component named "rotated" on this basis.
- Group C steel objects (probed, no crash):
  - `UnfoldedStraightBeam(Polyline3d section, start, end, vZ, t)`: the section must be a LOCAL 2D polyline (z = 0, origin on the beam axis; local x → world −Y, local y → world Z in one sample, mirror unconfirmed). A world-YZ section collapses to a flat strip with no error. Thickness is added outside.
  - `SpecialPart(Matrix3d)` + `SetBlock(name, scale)`: scale 2 reads back 1 (ignored); a missing block name writes with no error, empty BlockName and no body → pre-check the block exists, verify body.
  - `CompoundStraightBeam(...)` + `CreateComponents(...)`: no args / class `Compound2W` build 2 members; class + a wrong type name silently gives volume 0 and 0 members; ProfName always empty. Without a valid class/type list, verify only by volume > 0 and `getCompoundElements` count (never read Compound*Name).
- General rule: AS often accepts wrong inputs silently (empty/flat/unchanged object, no exception). Every new object kind's probe matrix must include at least one deliberately wrong input to see whether AS errors or silently produces garbage; when silent, the component needs its own pre-check plus a geometry read-back.
- Find API shapes by reflection with the repo tool `tools/sigdump` (MetadataLoadContext over `AutoCAD 2027\ADVS\AS*Mgd.dll`; `dotnet tools/sigdump/bin/Release/net10.0/sigdump.dll [--dll X.dll] [--grep regex] Full.Type.Name`; keep it in the repo, scratch copies get pruned). `GetModeler` returns `Autodesk.AdvanceSteel.Modeler.ModelerBody` (Volume, Vertices, IntersectWith(Plane|Curve3d), ClosestPointTo, Contains), not `Body`; enums nested in a class are addressed `Outer+eEnum`. Older notes: (`ASDLL=<dll>` picks the assembly, e.g. `UserInteraction` is in ASObjectsMgd, `DatabaseManager` is in none of the *Mgd DLLs sigdump loads) before coding; guessing type names (e.g. `RectangularBoltPattern`) wastes builds. Geometry types (`Polyline3d`, `Matrix2d`) live in `ASGeometryMgd.dll`, not `ASObjectsMgd.dll` (sigdump: `ASDLL=ASGeometryMgd.dll`); nested enums such as `eContourTypes`/`eFilletTypes` are on `FilerObject` (`typeof(FilerObject).GetNestedType(...)`). sigdump's MetadataLoadContext throws on `Grasshopper.dll`; inspect Grasshopper types (events, enum values, event-arg props) with a small Rhino Python script that reflects `clr.GetClrType(...)` and writes to a result file, launched like the canvas generators.
- New-feature order that worked every time: fetch the Dynamo source → sigdump ctors → one `debug.*` probe with a small labelled matrix (each variant on its own plate at a distinct Y, report removed volume + bbox of NEW body vertices to see where the cut landed, plus a variant whose plate origin is not a vertex to expose the local CS) → findings doc + commit → sync + GH component + test → canvas visual check with the user.

## Existing objects into GH (selection / extract) — measured
- Dynamo's `SelectAdvanceSteelObjects` maps an AutoCAD selection to AS objects with `FilerObject.GetFilerObject(ObjectId)` (`src/DynamoAdvanceSteel/SteelAppInteraction.cs`); `FilerObject.GetFilerObjectByHandle(string)` also exists. Our server instead reads `Editor.SelectImplied()` and maps each CAD id back through a `GetReprId(fo).Handle -> FilerObject` dictionary built over `GetModelObjectIds`. The pick-first set survives the user switching from AS to Rhino and right-clicking "Get selection from AS" (canvas-verified).
- Read-only components (selection, filter, by-type, extract) derive from plain `GH_Component` (shared `QueryComponentBase` with `Call`/`Ready`), NOT `LiveLinkComponent`: removing them must never send `component.delete`. Store picked handles in `Write/Read(GH_IWriter)` and re-validate them each solve (missing → warning, dropped).
- Return one output item per input handle (null + warning for missing / wrong-kind handles) so downstream lists stay aligned. Expose the AS .NET class name as the type string, and list types present in the model when a filter matches nothing.
- `model.list` only returns TAGGED objects: tests and queries over baked/manual objects need a separate untagged listing (`objects.bytype` with volume + holes). Build "existing" fixtures by creating with GH, `BakeToAs()`, then removing the component (`allTagged` must read 0); keep the fixture script in `tests/gh/canvas/`.
- Extract API: beams `GetPointAtStart()/GetPointAtEnd()`, `ProfSectionType + "#@§@#" + ProfSectionName` (feeds the create components directly), `SysLength`, `GetLength()`, `GetStandardWeight()`; bent `Get3dSystemlineArc(out CircArc3d, true)` (Start/Mid/EndPoint); poly `GetPolyline(true).Vertices` (reject if any `VertexInformation[i].Radius > 0` rather than drawing arcs straight). Plates `GetBaseContourPolygon(0, out pts)` (no features), `Thickness`, `GetDefinitionPlaneCS()` (origin = first vertex = PlatePolycut offset base), `GetPhysLengthAndWidth`. Bent beam `GetLength()` = arc length at the section's OUTERMOST edge, `(R + half section width) × arc angle` (measured R 1500–5725, 30–180°, horizontal and vertical arcs; same for every body context), while the body is swept along the system line (volume/area ≈ SysLength). Use SysLength for the system line and say so in the output description.
- Prove an extractor with a round trip: feed extracted start/end/section or contour/thickness into the create components and require identical volume.
- A point-along-beam component should accept one beam + N distances (N points), so a GH Series can lay out repeated connections along an existing member.
- Writing to EXISTING objects (properties, Dynamo `Property.SetObjectProperty` / `SteelObject.SetUserAttribute`): never put the Live Link tag on the object (component delete would erase the user's member). Keep a separate XData entry (`ASLL_PROPS`: component id, original values, applied values) and give it its own lifecycle hooked into `DeleteComponent`/`BakeComponent`: delete → restore originals and drop the entry; object or name removed from the input → restore that value; Bake → keep values, drop the entry, lock the component. Refuse objects carrying the Live Link tag (their create component's `properties` input owns them and a rebuild would overwrite) and objects held by another property component. Record originals only on the FIRST write (an update restores originals before reapplying). User attributes: `AtomicElement.GetUserAttribute(idx)/SetUserAttribute(idx, v)` with idx 0..9 (Dynamo's 1..10 minus one); expose as `UserAttribute1..10`. Test: create, unchanged re-solve, change one value (originals unchanged), drop a name, drop an object, refusals with model unchanged, delete restores, bake keeps + survives delete.
- Modifying EXISTING beam geometry (Dynamo `Beam.SetSystemLineStartPoint` / `SetSystemLineEndPoint` / `SetSection`), probed: `SetSysStart(pt)` / `SetSysEnd(pt)` return bool and move one end; handle is kept; plane cuts and copes follow the moved beam; moving back restores the exact original volume, so delete-restore is safe. Hazards AS does not report: connected bolts/anchors/studs/welds do NOT follow (left off the beam); `ChangeProfile(type, size)` with a bogus name still returns success and the body collapses; on a bent beam moving an end recomputes the 3-point arc (radius and mid change); start == end gives a zero-length beam. Connectors CAN be carried along: `TransformBy(T)` with `T = newCS; T.PostMultBy(oldCS.GetInverse())` (Matrix3d in ASGeometryMgd; beam CS from `SysCSStart`/`SysCSEnd`) moves bolt/anchor patterns and shear-stud Connectors rigidly, holes follow, count unchanged (translation + rotation measured). The stud's auto WeldPoint does NOT follow by itself: transform it too. Use the FIXED end as pivot (end moved → `SysCSStart`, start moved → `SysCSEnd`); pivoting on the start for a start move slides every connector with it. Classify connectors (any eAssemblyLocation in `GetConnectedObjects`): movable = bolt/anchor connected only to this beam, studs + their weld; blocking = bolt also through another part, weld between parts, Live-Link-tagged connectors (their component's rebuild would undo the move). After moving, reject when a connector lies beyond the new beam length (projection on the axis) or the hole count changed; restore uses the same transform without blocking checks. Also pre-reject: non-straight beams for point moves, unknown sections (`ProfilesManager.GetProfileType` null or `Dummy`), new point < 1 mm from the other end, beams carrying the Live Link tag. Ownership = same pattern as properties but keyed PER FIELD (`ASLL_MOD`: start / end / section → component, original, applied) so different components can own different fields of one beam; hook RestoreAll/ReleaseAll into the same delete/bake paths. Read the current section back as `ProfSectionType + "#@§@#" + ProfSectionName`. Probe with plane-cut/cope calls copied from the existing syncs (2-arg `Set` after AddFeature), never re-typed from memory.
- Modifying EXISTING plates (no Dynamo node; named `Plate.SetPolygonContour` / `Plate.SetThickness` after the Beam.Set... pattern), probed: `SetPolygonContour(Point3d[])` and `Thickness` keep the handle, restore is exact, vertex cuts and contour notches stay attached. AS silently ignores thickness ≤ 0 and any contour not on the plate plane (parallel offset or non-planar), accepts a self-intersecting contour (volume 0), and leaves connected bolts hanging off a shrunk contour. Pre-reject: vertex > 0.1 mm off the `GetDefinitionPlaneCS` plane, crossing edges / coincident vertices, vertex-count change when the plate has `PlateFeatVertFillet` (tied to vertex index), any connector point outside the new contour (`PartFootprint.FirstOutside`), any PlateHoles hole outside it (walk `GetFeatures(false)` → `ConnectionHolePlate.GetElementOrigins(out pts)`; AS would cut a notch or nothing), thickness ≤ 0. The plane check uses the plate's own `GetDefinitionPlaneCS`, so it holds for tilted and vertical plates (verified 30° about X and normal +X). Same per-field ownership pattern (`ASLL_PMOD`: contour / thickness). In tests, a refusal case for field X must use the component that already owns X on that object, else it is refused earlier as "already changed by another component" and tests the wrong rule.
- Modify-existing persistence test (verified for beam end, section, plate contour/thickness and a bolted beam move): phase A sets values + `doc.save` and stores component GUIDs; phase B in a NEW AS process checks the values and the per-field record (held by the same GUIDs), re-creates one component with `NewInstanceGuid` + same input → `unchanged`, then sends `component.delete` per GUID and requires the exact originals (including connectors moved back, hole count unchanged).
- Give modify-existing syncs a read-only test RPC that returns the object's current values, its per-field record and (for beams) every connected connector with points + movable/blocking classification (`beammod.connectors`); tests and canvas readbacks then assert positions without extra probes. When asserting a bolt pattern's position after a rigid move, use the centroid of `GetMidpoints`, not one bolt (each sits half a spacing off the centre).
- Canvas for modify-existing components: build the existing object with a fixture script (create in GH, add a feature, `BakeToAs()` both, check `allTagged` 0), then a canvas of Select → Filter(type) → modify component fed by a slider; steps for the user: pick in AS → right-click Get selection → look → drag → delete the component and check the original returns. The answer to ask for is the visual of the feature following, and the restore after delete.

## Beam options (Dynamo-AS parity) — measured
- Component names match Dynamo-AS `nodes.md` (e.g. `BeamCope.ByRectangularOrthoCope`, `RectangularBoltPattern.AtCentrePoint`); inputs deliberately differ (plane, text enums, explicit dx/dy/diameter/thickness). Dynamo's cornerType/end/side are numbers; ours are text.
- `beam.RefAxis` (enum kUpperLeft=0 ... kLowerRight=8, kContourCenter=9, web variants 101/104/107) is settable after construction on StraightBeam, PolyBeam and BentBeam; section moves accordingly (check vertex bbox). On a bent beam it also changes Volume (arc radius shifts); arc length does not.
- `Beam.SetCrossSectionMirrored(true, null)`: set RefAxis first, then mirror; mirror flips about the reference axis (only visible with an off-centre refAxis or an asymmetric section).
- ZAxis rotates the section for straight and poly beams (length-independent, direction only; +Y lays a UB flat, (0,1,1) = 45°). For `BentBeam` the ctor's vector is NOT a section orientation (+Z/+Y/+X identical, (0,1,1) changes extents and volume): do not expose it.
- Cope corners: `BeamNotch.SetCorner(kStraight=0|kRound=1|kBoringOut=2, radius)`. Round/boring with radius 0 silently falls back to straight and reads back kStraight: reject that combination (and straight with a radius) server-side instead of trusting AS.
- Optional-input rule for existing components: omit defaults from the hash string (sysSys, not mirrored, straight) so upgrading never rebuilds old objects; apply RefAxis/mirror inside the verify step and read each back; validate ZAxis parallelism only when the user passed one explicitly (the 0,0,1 default must keep vertical columns working).
- String properties (AtomicElement): `Material`, `Note`, `Coating`, `Denotation`, `Assembly`, `ItemNumber` are settable (`MaterialDescription`/`CoatingDescription` read-only) and survive `DatabaseManager.Open` reopen. AS does NOT validate values (a bogus Material is stored without error) and no catalog-listing API was found, so only read-back can be checked. Persistence across QSAVE + a fresh AS process is verified for straight/bent/poly beams and plates. GH re-solve does NOT notice manual edits in AS (the hash covers inputs only). Expose them as one optional `properties` text list of `Name=Value` (split on first `=`, case-insensitive names, reject unknown/duplicate/control chars), added to the hash only when given; share one ValidateProps/ApplyProps/PropsHash/TryParseProps across beam, bent, poly and plate, and have `model.list` read them via `AtomicElement` so plates are covered.
- Poly beam refAxis/zAxis behave like straight beams (section moves/rotates, volume unchanged); bent beam refAxis changes Volume only. For C# edits containing escape sequences (`'\n'`, `\\`, verbatim paths) use the `patch` tool with literal old/new strings, one call per hunk: a Python `str.replace` heredoc mis-escapes them, its assert fails, nothing is written, and the following build still succeeds on the OLD source (check the patch output before building). Python patch scripts containing C# with `'`/`$` quoting break bash heredocs ("unexpected EOF", nothing runs): write the patch script with write_file and run it with `python -I`. Pass native Python paths from bash as `$(cygpath -m ...)` (C:/...); a `/c/...` path from `cygpath -u` gives FileNotFoundError, the patch silently does not apply, and the next step runs the old file.
- No API to list profile types: `ProfilesManager.GetFirstProfileName` threw NullReferenceException for every candidate name, so asymmetric-section tests need a section string obtained another way.

## Test harness recipe
- Headless GH test: Rhino Python 3 script loads the plugin from `%APPDATA%\Grasshopper\Libraries\ASLL.LiveLink` (use a test-only folder, delete after; never touch the user's `HH.AdvanceSteel.LiveLink`), creates a `GH_Document`, adds the component, sets `PersistentData`, calls `ExpireSolution/CollectData/ComputeData`, reads `RuntimeMessages`. Query AS via a debug-only RPC (`ASLL_DEBUG=1`) such as `model.list` / `model.stats`.
- For every new component test: create, re-solve unchanged (handles stable), change one item (only it updates), each rejection case (model unchanged), Bake (objects stay, tag dropped), remove component (tagged objects deleted).
- Start AS from a copy of a base DWG each run; kill only the PIDs you started; remove the test plugin folder at the end. This holds for quick fix-and-retry steps too: never `Get-Process Rhino | Stop-Process` (or kill by image name) to clear a stuck generator run, since it also kills the user's own Rhino/AS. Capture the PID printed by the launch script and stop that PID; if the PID is lost, list processes and ask before stopping.
- When the user's own AS is running a live link, starting your own AS overwrites `%TEMP%\asll_pipe.json` (and `asll_spike.log` if you delete/move it), so the user's open Grasshopper reconnects to YOUR AS on its next solve. Back up both files first, tell the user not to touch GH until done, and after stopping your PID restore the backup (or ask them to re-run `ASLL_PIPE_START`). Never close AS/Rhino the user opened (e.g. after they followed an install guide).
- The Hermes scratch dir prunes files idle 24 h, so runner templates kept only there (the Rhino launch `.ps1`, the AS-launch `run()` shell wrapper, `startas.ps1`, `run8.scr`, `asrpc.ps1`) silently disappear and every derived runner fails with "can't read rh10.ps1". Keep the canonical copies in the repo under `tests/gh/runner/` and derive per-test runners from those with sed (test filename + result filename); only the base DWG stays outside the repo. For regressions after a shared-check change, generate one `rh_<test>.ps1` per test and append `echo "== t"; run <result> rh_<test>.ps1` lines to one runner (each run gets a fresh AS on a fresh DWG copy); split into chunks of ~5 tests so each call stays under the 600 s foreground cap. `asrpc.ps1 -Method debug.X` replaces a separate probe client.
- Guard every test against passing vacuously: assert the preconditions the scenario depends on (features actually created before Bake, `BakeToAs()` returned 1, expected rollback count) inside the test. A wrong output index (Output[0] is status vs Output[1] handles, it differs per component) made every feature sync fail silently and a stress test still reported PASS; suspicious constants in the PASS details (e.g. `bake n=0` everywhere) mean the run is void — fix and rerun, and say the first run was invalid.
- If the user's own AS has `NETLOAD`ed the DLL from `src/AsLiveLink.Server/bin/Release`, a normal build fails with MSB3021/MSB3027 (file locked). Build into scratch instead: `dotnet build -c Release -o <scratch>/srvbuild` and copy from there into the test run folder; tell the user `bin\Release` updates on the next build after they close AS.
- GH runtime messages have three levels: when asserting a component's feedback, read Error, Warning AND Remark (`RuntimeMessages(GH_RuntimeMessageLevel.Remark)`); informational hints such as "no object of type X, types present: ..." are Remarks, and a test reading only Error/Warning reports a working component as failing.
- Before launching Rhino on a canvas, confirm the AS PID from THIS run is alive and `asll_pipe.json` exists: when a fix-and-retry step re-runs only the generator + Rhino launch after an earlier call aborted before starting AS, Rhino opens against no server (every RPC times out) and the user gets a dead canvas. Keep the generator, AS start and Rhino launch in one call, or check `Get-Process -Id <pid>` first.
- Rhino `-_Grasshopper _Enter` on the command line may not open the window; to open a .gh reliably launch Rhino with `/runscript="-_Grasshopper _Window _Show _Document _Open <file> _Enter"`.
- Persistence (two-phase) test: one script with `PHASE = "A"|"B"` (sed-switched copies). When deriving the runner from an older one by sed, grep the result for the OLD test filename: an unreplaced source path makes phase B run the old test, and the symptom is only a missing B result file / empty PASS counts. Phase A builds the components, checks read-back, calls `doc.save` and waits for the DWG mtime to change, then stores each component's `InstanceGuid` + handle in a JSON state file. Kill AS and start a NEW AS process on the same DWG plus a new Rhino. Phase B recreates the components with `comp.NewInstanceGuid(Guid(saved))` and identical inputs, and expects `unchanged` + the same handles + the values read from the DWG. This proves tag, hash and data all survived.
- `model.stats.objects` is 1 on the empty GBR template: handle 223 comes with the template, `DatabaseManager.Open` returns null for it, and it has no tag. Count Live Link objects with `allTagged`, not `objects`. To identify unknown objects, list each `GetModelObjectIds` entry (type, tagged, handle) on the saved DWG AND on a copy of the empty base DWG, then diff the two lists.
- Compare model snapshots before/after a rejection after rounding every volume field the snapshot carries (beam `volume`, plate `plateBodyVolume`; ~1e-8 to 1e-10 float noise between reads of the same object, worst on tilted plates); on failure print only the differing fields per item (a truncated JSON dump hides the cause).
- Never round a read-back and then compare it with a tolerance of the same size as the rounding step (100.0006 rounded to 0.001 fails `< 1e-3`): compare raw values, or keep the tolerance ≥ 2× the rounding step.
- When a regression count differs from the number in an old doc, count the test's assertions before suspecting lost tests (e.g. `check(` calls × loop iterations, and `git log` on the test file to confirm it is unchanged); if the doc was wrong, correct that sentence in place and note the correction in the new result doc.
- RPCs that filter by component (`anchors.list`, `*.list` with `componentId`) match the server's `InstanceGuid.ToString("N")` (no dashes); passing `str(comp.InstanceGuid)` returns an empty list and makes every positive case fail while refusal cases still pass. Pass `comp.InstanceGuid.ToString("N")`.
- Count results with `grep -c '^PASS'`: a bare `grep -c PASS` also counts the `RESULT: PASS` line, so totals drift by one between runs and look like lost tests.
- A test script that is not PASS/FAIL formatted (older step-print style) reports `0 PASS 0 FAIL`: that is no result, read the output yourself and count.
- To retarget a runner `.ps1` at another file, write the new first line (`$gh = '<windows path>'`) with echo and append the remaining lines with `sed -n 2,Np`; sed-substituting a Windows path containing backslashes breaks the expression ("no previous regular expression") and the step silently runs nothing.
- PowerShell probe clients: `$null = Fn` swallows the function's printed output; use `Write-Host`. Embed `§` via `[char]0xA7` (script-file encoding mangles it). `sed` eats backslashes in csproj paths; use patch/python. A nested `EOF` inside a heredoc ends the outer one early.
- Inside a bash `run(){ ... }` helper, build the PowerShell `-File` path with `$(cygpath -w $SC/$2)`, never `"$SCW\\$2"`: the backslash swallows the `$` and PowerShell gets a literal `scratch$2`, Rhino never starts, and the run reports an empty `PASS` count while AS was launched for nothing. An empty PASS count with "No such file" on the result file means the test never ran: say so and rerun.
- Long multi-launch test chains exceed the 600 s foreground cap and run as a background process with a completion notice; do not rerun.
- A failing readback on a first-time design is usually a wrong assumption about AS semantics, not a tolerance problem: fix the check's meaning (as with N=1 bolts), do not loosen the tolerance. When the SERVER rejects correctly but the test fails, check the test first: use the server's own tolerance in assertions, and re-derive which side a plane normal removes before writing "misses / removes all" cases.
- New feature kinds also need: a test that two different feature components on the same part coexist and delete independently, and a parent-rebuild test (change the beam/plate so its handle changes: old feature disappears with the old part, re-fed handle recreates it).

## Misc pitfalls
- GitHub repo names cannot contain spaces; convert to hyphens.
- Mark unverified mappings/assumptions `[待驗證]` in docs until proven on the host.
- Fresh clone: set repo-local git identity (noreply email) before committing.
- A long compound terminal command that starts AS/Rhino and kills a PID can hit an approval timeout and be blocked unrun (the user is then asked each time AS is launched). Do not retry or rephrase when blocked: report what was and was not run, list options, and wait for the user's go-ahead. Prefer fewer, larger probes per AS launch.
- When the user answers "yes" to an install/upgrade step on this PC, check it (installed `.gha` `ProductVersion`, new `ASLL_runs`/output files newer than the request) before recording it; if the machine state disagrees, record "未明確確認" and ask which machine, instead of marking it verified.
- When the user says a manual canvas step "succeeded", confirm via AS state before recording it (e.g. Bake: tagged count drops but object stays; double-click: delete the object via debug RPC first, then see it reappear with a new handle). For features, simulate the user's manual delete with a debug RPC that walks hosts' `GetFeatures(false)`, finds the feature by handle and calls `host.DelFeature(f)` + `host.WriteToDb()`; after the double-click, check that only the deleted features came back (new handles) and every untouched object kept its handle.
- Run canvas acceptance as numbered steps with one user action each (visual check -> double-click after a simulated delete -> Bake), reading AS state between steps; avoid slider drags in a step whose purpose is something else, so a known unrelated bug (orphan beam) cannot confound it.
- Probe runs: chain `dotnet build` with the copy/launch step and stop if it fails; a failed build leaves the OLD DLL, so AS runs stale code and the printed output is not a result for the new probe.
- Selecting AS objects by handle: AS model objects (`AstBeamStraight` etc.) cannot go into `Editor.SetImpliedSelection` (eInvalidInput, same in script-launched and user-driven AS). Select their display entity instead: inside `new DocumentAccess(null, true)`, `DatabaseManager.GetReprId(filerObj)` -> its `.Handle` -> `doc.Database.TryGetObjectId(new Handle(hex))` (CAD class `AstBeamRepr`) -> `SetImpliedSelection` -> `SelectImplied` reads back OK. Verified for beams, plates, bolt patterns and multi-select; a missing handle goes to a `missing` list. Cope features have no repr (not selectable this way). Read-back only proves set size; on-screen highlight still needs the user's eyes. The GH right-click "Select in AS" is wired (sends the first output's handles; the cope component sends the beams it cuts).
- After a `write_file`/`patch` returns an error, re-read the file before writing docs that claim the change; a doc stating a refactor landed while the write was refused had to be corrected. For a full rewrite of an existing doc, `write_file` can keep refusing ("last read was partial") even after a full re-read; do not loop on read/write: apply the rewrite in one `execute_code` script that reads the file, does exact-substring replacements each asserted `count == 1` (section moves via index slicing), writes it, and runs the link check in the same script. Then confirm with `head -1` and a link check (every `](X.md)` target exists) before committing.
- `model.list` exposes `volume` for beams AND plates (`b?.Volume ?? p?.Volume`) and `holes` (NumberOfHoles), so every new kind has a geometry read in tests; a plate volume reading 0 means the list code only covers beams.
- Test-expectation pitfalls seen repeatedly: the same component index moved to another host reports `updated`, not `created`; an empty required list input stops the solve before any sync (AS unchanged, consistent across components); state left by earlier steps of the same test (a feature moved away, a cut still present) changes later volume expectations, so recompute expected values from what is currently on the host. When a case is meant to hit one specific rejection ("partly overlaps"), check its geometry on paper first: a test rectangle lying entirely inside an existing cut hits a different rule ("no material"); write both cases separately.
- When a new kind exposes a gap in a check shared with an older component (e.g. hole-count-only placement), add the same failing case to the OLDER component's test first, confirm it fails there, then port the fix and re-run both; record it in STATUS known issues as unverified until that test runs.
- To prove a fix closes a real hole (not just that the new code rejects), run the SAME new test against the old server. Simplest: copy the changed .cs files aside, `git show HEAD:<path> > <path>` for each, `dotnet build -c Release -o <scratch>/olddll/bin`, copy the new files back and rebuild; then sed a copy of the runner so its server-copy `S=` line points at the old bin. (Alternative: `git stash push -- <files>`.) Report old vs new per case in a table. If the new test also passes on the OLD DLL, the claimed loophole was wrong: read which check rejected each case in the old run's error text (e.g. hole-count read-back), correct the BACKLOG/doc claim in place, and redesign the negative cases against what the old code truly let through before shipping the fix. Design each negative case on paper first so it actually lands off the part (a circle that happens to fit inside proves nothing about the old code; say so instead of claiming the old code was also wrong).
- Test harness: look up GH component class names from the source (`grep '^public class .*Component'`) before writing a test; Dynamo node names do not map 1:1 to class names (`RectangularAnchorPatternComponent`, not `...AtCentrePointComponent`), and a wrong name aborts the whole test with AttributeError. Hole counts are cumulative on a shared host across test steps: assert deltas, not absolutes.
