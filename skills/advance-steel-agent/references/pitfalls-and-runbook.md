## Pitfalls

- Keep every current-frame capture validation, including null rejection, inside the frame-discard failure path. Otherwise a thrown validation error can retain an earlier staged snapshot that a later completion publishes. Keep owner/sequence guards outside that discard boundary so foreign-thread or stale callbacks cannot poison a healthy newer frame. Test Armed and Applying states, preserving active-batch/recovery identity; managed Discard is not native compensation.

- Prove a nominal AutoCAD-only counterfactual with actual native module paths and active object classes; neither `/product ACAD` nor a VANILLA profile proves AS-free execution. Existing bundles/native object enablers can load before your probe. If the clean-host gate fails, reject the arm before mutation rather than disabling installed plugins or changing shared loading settings without scope.
- Identify the exact filename and PID/lifetime of an unsigned-executable prompt using readonly dialog metadata; startup security may concern an existing bundle before NETLOAD reaches your pinned probe. Never auto-approve it or change security/trust settings to bypass it. If the modal prevents scoped cleanup, retain the exact owned identity and explicitly report that zeroDocs and OS exit are unverified.

- Observe the whole active Undo/Redo command, not only the gap after CommandEnded. A different native object can be opened for write during UNDO while its own IsUndoing is false; that flag alone does not mean callback updates are safe. Use only event-supplied readonly metadata in diagnostic callbacks (no transactions, object reopen, Xrecord Data or AS reader), cap/count errors and dropped/reentrant events, detach before serialization, and correlate the actual native command history. Treat an extra normal write as a root-cause candidate until a scoped causal control isolates it; do not blame an installed plugin from a native-reactor bridge stack alone.

- Anchor native Undo/Redo history before the UNDO token, not at the last writer-name occurrence: AutoCAD UNDO echoes the undone command name, so rfind(writer) can select that echo and falsely remove the Undo evidence. Regress against the actual captured fragment, preserve the original failed run, and accept repaired parsing in a separate parent receipt. Capture only after native byte restoration and clean Save; discard stale HWND-bound sessions before TEXTSCR, restore GRAPHSCR in finally, then fresh-bind the same lifetime/PID/document and verify the restored graphical frame before Close/reopen.

- When diagnosing native Undo around a managed read command, vary CommandFlags.Session versus Modal independently of NoUndoMarker, document locking and ForRead transaction Commit. Session plus NoUndoMarker is not evidence that the observer cannot affect undo history; verify actual stage and immediate single-Undo bytes in a dedicated no-Redo arm. A Modal single-Undo improvement does not establish a fix for adjacent Redo or authorize changing installed plugins; keep the accepted scope exact.

- Separate actual stage readback, first-Undo observation, post-pair bytes and conditional restoration Undo in diagnostic receipts. Removing observers also removes evidence: a successful Commit plus original bytes after a pair is not a new independent Undo PASS, and corrupt bytes after a pair can mean ineffective Undo rather than successful Redo. Verify stage independently before the adjacent pair, label the observer/context explicitly, and never equate a later restoration snapshot with the first Undo state.

- Update hash pins by exact field name, never global text replacement when source, previous fixture and current normalized work copy initially share bytes. Protected original/previous hashes must come from an immutable authorization/lineage record and remain independent of the mutable control-model hash; verify the protected files before and after each experiment.
- Resolve the native report phase filename separately from its archive name before issuing a command. A timeout waiting for an archive-named file can occur after the mutation completed and wrote its fixed phase file (abort.json/stage.json); inspect the real phase report and exact host state, never replay a possibly executed command to manufacture the missing archive. After a successful structural correction and actual save-close-reopen, resume metadata tests from that accepted valid baseline without repeating ChangeProfile.

- Review the exact installed worker binary proven loaded by runtime Location/MVID/hash before assigning Idle/reactor causation; source in the current worktree may not be that binary. Scan direct static subscriptions and undo-control calls, retain undecoded/reflective/external edges as unknown, and count IL bodies by unique MethodDef token rather than overloaded method name. Pair this with nonmutating exact-module Queue/registration/response count snapshots before/after the native read; reject wrong PID/module, missing/read-error/negative/bool counts. Empty sampled states do not prove continuous inactivity or exclude historical transient/inflight requests, and do not authorize disabling a startup plugin.

- Capture exact-PID native command history when REDO leaves original bytes: distinguish `Nothing to redo` from an executed redo that restored the wrong content. Read the owned AutoCAD Text Window through UIA after restoration; do not alter global logging settings. TEXTSCR and document reopen can change the effective application HWND, so revalidate the current frame against the same exact PID/process lifetime and document path, restore GRAPHSCR before normal operations, and keep foreign/unknown HWND rejection intact. After a submitted Close(false), recover by proving zero documents rather than replaying Close. Keep missing OS exit-code evidence separate from observed process exit.
- Verify effective in-process CLR bindings for diagnostic dependencies, not only package file hashes and successful NETLOAD commands. Record actual Assembly.Location, MVID and backing-file hash for executing probe/store/reader types and compare with the intended pin; independently compare runtime MVID to the backing PE Module MVID to detect an older loaded image behind a changed file. Reject missing/duplicate simple-name bindings, foreign PID, different path/hash and unreadable backing files before treatment. A readonly binding-only run must discard-close without Save and verify source/work on-disk hashes remain unchanged; report in-memory DBMOD and nonzero OS exit separately from a passed diagnostic gate; startup-loaded or cached assemblies can otherwise invalidate a claimed treatment. Record a missing runtime binding check as unverified, not as evidence that a conflicting assembly caused the failure.

- Keep REDO adjacent to UNDO as required by the AutoCAD command reference: an intervening metadata observation command invalidates that experiment even if it is NoUndoMarker. Observe Undo absence in one cycle, and use a separate identical clean Stage cycle for an immediate UNDO/REDO pair; never replace a failed Redo with an explicit restage and label it Redo success. Independent persistence after a disclosed restage can still be verified, but overall acceptance retains the Redo failure.
- Use explicit `DocumentAccess(null, true)` for native read-oriented AS contexts after validating installed overload semantics. A write-capable default followed by Commit may affect Undo history despite an API being named ReadScope. Preserve the exact selected document/database/GUID/transaction guards and native scope release failure handling. Build/pin the candidate separately, then compare the real native full read and Undo behavior before promoting the source change; do not install or publish merely because a read-only compile passes.

- Isolate ownership Undo observers before blaming storage: remove event-reactor transaction reads and post-Stage AS read leases, then observe the reserved Xrecord with a NoUndoMarker AutoCAD ForRead-only command using the previously verified representation ObjectId. Distinguish native beam Handle from representation Handle; resolve through GetFilerObjectId/GetReprId and native GUID, never by converting the native Handle. A raw metadata Undo can pass while Redo remains broken, so accept only the exact gate observed; compare representation class/id/extents and keep full native geometry/persistence gates separate. Successful AS read-scope disposal may Commit its DocumentAccess rather than Abort, so inspect the actual release sequence instead of inferring it from a read-oriented name.

- Diagnose a dynamic pywin32 `AttributeError` at the real name-lookup seam before assuming a missing CAD API: `CDispatch.__getattr__` catches `ole_error` from `GetIDsOfNames` and can disguise native busy HRESULTs as missing HWND/SendCommand. Preserve only known busy HRESULTs through an instance-scoped non-ole_error exception with the native cause; retain unknown-name rejection, exact PID/HWND checks and bounded readonly polling. Resolve a command callable under a readonly bounded wait, then invoke once outside retries; never replay a possibly executed mutation. A real pywin32 wrapper with an injected raw GetIDsOfNames error provides an offline RED/GREEN regression without launching CAD.
- Verify native committed metadata with an independent read, and keep Abort, owner-negative, Undo/Redo and save-close-reopen as separate gates. Readonly commands can affect Undo markers, but adding NoUndoMarker does not by itself prove Undo correctness for Session commands plus Advance Steel DocumentAccess. If UNDO 1 leaves metadata present, preserve that RED observation, inspect actual undo recording/command context, and do not weaken acceptance or blindly increase Undo count.

- For a known owned Document Manager, inspect each category and its `Checking status` node through PID/HTREEITEM-scoped native `TVM_SELECTITEM` with `TVGN_CARET` read-back; do not use pywinauto `.select()` where it changes global focus. Category selection alone may leave `Checking status` unchanged indefinitely. Selecting the status node can synchronously rebuild the entire tree and change it to `Empty`; native pointers may be reused for different nodes. Accept only explicitly evidenced same-category transitions: verify native return TRUE, final caret path/text/parent, native count consistency, and disappearance of the original composite item identity (pointer+parent+text+path), not pointer absence alone. Keep Unknown, unrelated category, pending original identity and ambiguous counts fail-closed.
- For the no-detail ownership fixture, establish zero registered derived documents from all four actual native category statuses (Details, Bill-of-Material, DStV-Bill-of-Material, DStV-NC), each explicit `Empty` over bounded stable samples, selected visible pane rows=0, and final tree without pending/Unknown statuses. Keep this fixture-specific registration acceptance separate from arbitrary file-reference audits, native metadata write/Undo/persistence acceptance, and clean OS exit. Preserve each rebuild evidence JSON separately; a single overwritten mismatch file loses earlier transitions.

- Stage the full diagnostic HH dependency closure and explicitly pin its actual accepted build, not an older proposal DLL solely because its hash still matches the original proposal. Preserve the native RED/repair/GREEN provenance; missing Domain/adapter dependencies and a stale ReferenceEquals adapter are different failures. Avoid copying Autodesk SDK DLLs into the diagnostic package when the owned host supplies them.
- Keep run evidence paths short enough for all called Windows/.NET APIs; successful directory creation does not prove a long final result filename can be written. Exercise the exact output path before launching a host, and keep native cleanup independent from report serialization.
- Inspect the installed pywinauto API before native TreeView clicks: `_treeview_element.client_rect()` returns client coordinates, may return None for an unaddressable item, and `rectangle()` is not available in this installation. Reject None/invalid rectangles before sending mouse messages; do not convert client coordinates as if they were screen coordinates. For native tree evidence, compare raw TVM_GETCOUNT before/after with enumerated unique HTREEITEMs, validate parent links, and revalidate run-local item text/PID before selection; path strings or duplicate labels are not sufficient identity.

- Evaluate Document Manager settlement from recursively enumerated native TreeView item text, not only HWND captions such as `Tree1`. Record both pending-tree and literal-control counts, bounded stable samples and unreadable nodes; never ignore the tree count or promote a caption-only success flag. A stable `Checking status` label remains unresolved until actual hierarchy/right-pane evidence or matching-version documentation establishes whether it is an active scan or a persistent category; word matching alone does not establish that lifecycle. Verify predicates against recorded native snapshots before accepting delegated success flags. Empty hidden list views do not establish zero registrations, and searching list rows is not a Details TreeView selection; require exact scoped tree selection plus observed right-pane response. Preserve the original rejected JSON and add a separate parent assessment rather than silently rewriting historic results.
